# 출근 현황 화면 기획

홈 인사고과 카드의 **출근** 칸을 누르면 열리는 화면. 시안 A(한눈에 보기)와
B(월별 보기) 두 장을 기준으로 정리한다.

## 지금 있는 것

- `user_attendance(user_id, attended_on)` — 앱을 연 날을 하루 한 행으로 남긴다.
  본인 행만 select/insert 하는 RLS가 걸려 있다.
- `check_in_and_get_status()` — 홈 진입 시 오늘 출근을 남기고 누적 출근 일수를
  포함한 인사고과 지표를 돌려준다. 날짜는 `Asia/Seoul` 기준으로 끊는다.

즉 **데이터는 이미 다 쌓이고 있고, 마이그레이션 없이 화면만 붙이면 된다.**
`attended_on`을 월 범위로 직접 조회하면 A·B가 필요한 값이 전부 나온다.

## 먼저 정해야 하는 것: 근무일을 무엇으로 볼 것인가

이 화면의 성격을 가르는 유일한 갈림길이다. 시안에는 세 가지가 들어 있다.

- 8월 9일 일요일이 **휴무**
- "이번 달 근무일은 **4일 남았다냥**" (분모가 있는 진행바)
- 범례 **출근 완료 / 휴무 / 예정**

그런데 출근 테이블에 적어 둔 원칙은 이렇다.

> 연속(streak)이 아니라 누적이다. 길고양이는 매일 만날 수 있는 대상이 아니라
> 사용자가 통제할 수 없는 이유로 끊기는데, 그때 숫자가 줄면 복귀가 아니라 이탈을 부른다.

분모가 생기면 "못 채운 칸"이 보인다. 누적은 실패가 없는 구조인데, 진행바는
실패를 만든다. 둘 중 하나를 고르거나, 분모를 벌이 아닌 모양으로 만들어야 한다.

### 안 1 — 평일 근무제 (시안에 충실)

- 근무일 = 그 달의 평일. 주말은 처음부터 **휴무**.
- 진행바 = 이번 달 출근 / 이번 달 평일 수. "근무일 4일 남았다냥"이 그대로 산다.
- 평일에 안 나온 날은 **빈칸으로 둔다. '결근'이라는 말은 어디에도 쓰지 않는다.**
- 주말에 앱을 열면 **특근** 도장을 따로 찍는다. 분모에는 넣지 않는다 —
  분모를 늘리지 않으니 순수하게 이득만 되는 칸이다.

회사원 은유가 가장 진하고 시안 문구가 하나도 안 바뀐다. 대신 평일에만 분모가
있어서, 주말에만 고양이를 보는 사람에게는 빈 평일이 계속 쌓인다.

### 안 2 — 무휴 누적제 (기존 원칙에 충실)

- 근무일 개념을 두지 않는다. 지난 날 중 안 나온 날이 전부 **휴무**다.
- 범례 세 가지와 1:1로 맞는다 — 출근 완료(지난 날 ○) / 휴무(지난 날 ×) / 예정(앞날).
- 진행바 대신 **이번 달 출근 N일 + 누적 N일**을 나란히 보여준다.
- 문구는 "이번 달 근무일은 4일 남았다냥" → "이번 달은 4일 남았다냥"으로 바뀐다.

실패 칸이 구조적으로 없다. 대신 회사원 맛이 한 단계 옅어진다.

**추천은 안 1이다.** 출근은 앱을 열기만 하면 자동으로 찍히는 것이라 달성 난도가
사실상 0이고, 누적 일수는 어떤 경우에도 줄지 않는다. 그래서 분모가 생겨도
연속 기록처럼 무너지지 않는다. 다만 위의 두 가지 — **결근이라는 말을 쓰지 않는 것**과
**주말 특근을 이득으로만 두는 것** — 은 같이 가야 안전하다.

### 결정: 안 1 (평일 근무제)

하루의 상태를 다섯 가지로 둔다.

| 상태 | 조건 | 표시 |
|---|---|---|
| 출근 완료 | 평일 + 출근 | 주황 발도장 |
| 특근 | 주말 + 출근 | 발도장 + '특근' 라벨. 분모에 넣지 않는다 |
| 휴무 | 주말 + 미출근 | 회색 |
| 예정 | 오늘 이후 | 연한 회색 |
| (빈칸) | 평일 + 미출근 | **라벨 없이 비워 둔다. '결근'이라 쓰지 않는다** |

큰 숫자 "이번 달 출근 N일"은 평일·주말을 가리지 않은 실제 출근 일수다. 진행바만
근무일(평일) 기준이고, 바 아래 문구가 그 차이를 설명한다. 특근이 있으면 같은 자리에
덤이라고 덧붙인다. 바는 100%를 넘기지 않게 자른다.

## 화면 구성

### A와 B의 관계

시안 A 아래에 `전체 기록 보기 >`가 있으니, **A가 기본 화면이고 B가 그 하위**로 읽는다.

```
홈 · 인사고과 카드 [출근 18일]  ─탭─▶  A. 출근 현황  ─"전체 기록 보기"─▶  B. 월별 기록
```

상단 세그먼트로 A↔B를 토글하는 방식도 가능하지만, A의 "최근 출근 기록"과 B의
캘린더가 같은 내용을 두 번 보여주는 구조라 계층으로 두는 쪽이 덜 겹친다.

### A. 출근 현황

| 영역 | 내용 |
|---|---|
| 헤더 | 뒤로가기 + "출근 현황" |
| 히어로 | 발도장 배지 + "오늘도 출근 완료했다냥!" + 보조 문구 |
| 이번 달 카드 | "이번 달 출근" / 큰 숫자 N일 / 진행바 / 남은 날 문구 |
| 최근 출근 기록 | 최근 3일. 날짜·요일 + 상태 칩(출근 완료 / 휴무) |
| 꼬리말 | "성실한 발자국이 차곡차곡 쌓이는 중" |
| 링크 | 전체 기록 보기 > |

히어로는 **항상 "출근 완료"다.** 홈을 거쳐야 이 화면에 올 수 있고 홈 진입 시점에
이미 출근이 찍히기 때문이다. 상태가 하나뿐이니 문구를 분기할 필요가 없고,
대신 진입할 때 도장이 찍히는 짧은 연출을 넣으면 화면이 살아난다.

### B. 월별 기록

| 영역 | 내용 |
|---|---|
| 헤더 | 뒤로가기 + "출근 현황" |
| 제목 | "8월 출근 기록이다냥" |
| 캘린더 | 일~토 7열. 출근한 날에 발도장, 오늘은 주황 링, 선택한 날은 회색 원 |
| 선택 상세 | 고른 날짜 + 그날의 상태 카드 |
| 범례 | 출근 완료 / 휴무 / 예정 |

시안에 월 이동 장치가 없다. 제목 좌우에 화살표를 두고, **가입한 달보다 앞으로는
못 가게** 막는 걸로 정한다.

## 붙이는 방법

### 내비게이션 — 홈 스택이 필요하다

시안 두 장 모두 하단바가 그대로 보인다. 그런데 지금 `HomeTab`은 스택이 아니라
`HomeScreen` 한 장이라, 화면을 밀어 넣을 자리가 없다. 루트 스택에 넣으면 하단바가
사라진다.

동네 탭이 쓰는 `MapNavigator`와 같은 모양으로 `HomeNavigator`를 만든다.

```
HomeTab → HomeNavigator
            ├─ Home            (HomeScreen)
            ├─ Attendance      (A)
            └─ AttendanceMonth (B)
```

`MainTabBar`는 활성 라우트가 `HomeTab`이면 그대로 그리므로 하단바는 자동으로 남는다.
뒤로가기는 기존 `useGoBackOrHome`을 재사용한다.

### 진입점

`CrewProgressCard`의 출근 칸을 `Pressable`로 만든다. 지금 카드는 출근·수집·승진·재회
네 칸이고 나중에 각자 갈 곳이 생길 수 있으니, 칸 단위로 누를 수 있는 구조를 잡아 둔다.
접근성 라벨은 "출근 현황 보기".

### 데이터

마이그레이션 없이 클라이언트에서 직접 조회한다. RLS가 본인 행만 내주므로 안전하다.

```ts
supabase.from('user_attendance')
  .select('attended_on')
  .gte('attended_on', 월초)
  .lte('attended_on', 월말)
```

한 달 최대 31행이라 월을 넘길 때마다 그 달만 가져오면 된다. 누적 출근 일수는
이미 홈이 받아 둔 `crewStatus.attendanceDays`를 그대로 쓴다.

### 시간대 (놓치기 쉬운 부분)

RPC는 `Asia/Seoul`로 날짜를 끊는데 클라이언트가 기기 시간대로 월 경계와 '오늘'을
계산하면 어긋난다. 자정 직후나 해외에서 특히 그렇다. **KST로 고정하는 날짜 유틸을
하나 두고 A·B가 같이 쓴다.**

## 확인해야 할 상태

- 가입 첫날 — 이번 달 1일, 최근 기록 1줄, 캘린더에 도장 하나. 문구가 어색하지 않은지.
- 이번 달 출근이 0일인 달을 과거로 넘겨봤을 때.
- 월 경계 — 8월 1일에 들어갔을 때 7월이 비어 보이지 않는지.
- 오프라인/조회 실패 시 화면이 빈 채로 남지 않는지.

## 작업 순서

1. KST 날짜 유틸 + `attendance.api` (월별 조회)
2. `HomeNavigator` 도입, 라우트 등록, 출근 칸 진입점 연결
3. A 화면
4. B 화면 + 월 이동
5. 시뮬레이터에서 위 상태들 확인

1·2는 3·4의 전제라 먼저 가야 하고, 3과 4는 나눠서 진행할 수 있다.
