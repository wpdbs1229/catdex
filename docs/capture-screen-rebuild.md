# 촬영 화면 재작성

클라이언트 재작성의 1단계다. 촬영 화면만 실제로 동작시키고, 나머지 화면은 흰 화면 자리표시자로 둔다.
도메인 규칙은 `domain-rules.md`를 기준으로 한다.

## 범위

**이번 단계에 넣은 것**

- 촬영 화면(`src/features/capture`): 4:3 프리뷰, 배율 칩 + 핀치 줌, 플래시, 3분할 안내선, 전후면 전환, 갤러리 가져오기
- 촬영 결과 확인 화면: 누끼 미리보기, 누끼/원본 토글, 탐지 실패 안내, 다시 찍기
- `cat-vision` 네이티브 모듈(iOS/Android): 고양이 탐지 + 누끼
- `camera-zoom` 네이티브 모듈(iOS/Android): 기기 최대 배율 조회
- 내비게이션 뼈대: 탭 5개(홈·지도·촬영·도감·마이), 촬영만 실제 화면

**이번 단계에 넣지 않은 것**

- 시각 임베딩 (`domain-rules.md`의 "임베딩 결정" 참고)
- 업로드, 관찰 생성, 매칭 후보, 도감 등록 — 확인 화면의 "도감에 등록"은 안내만 띄운다
- 위치(지역 라벨) 수집

## 화면 구조

```
상단바   [X]              [플래시] [안내선]
프리뷰   4:3 고정, 핀치 줌, 안내선 오버레이
하단     배율 칩 (1 / 2 / 3 / 5 / 10 중 기기 지원분만)
         [갤러리]   ( 셔터 )   [전후면]
```

프리뷰를 4:3으로 고정한 이유는 개체마다 프레이밍이 달라지면 누끼와 매칭 품질이 흔들리기 때문이다.

플래시는 기본 꺼짐이고, 켜면 "동물에게는 눈부실 수 있어요" 문구를 함께 띄운다.

## 배율 설계

`expo-camera`의 `zoom` prop은 **기기 최대 배율에 대한 0~1 비율**이라, JS만으로는 현재 몇 배인지 알 수 없다.
라벨을 추측으로 붙이지 않기 위해 `camera-zoom` 모듈에서 기기 능력을 조회하고 `src/features/capture/camera-zoom.ts`에서 환산한다.

| 플랫폼 | expo-camera가 적용하는 식 | 매핑 | 조회 대상 |
|---|---|---|---|
| iOS | `videoZoomFactor = pow(maxFactor, zoom)` | 지수 | `activeFormat.videoMaxZoomFactor` |
| Android | `zoomRatio = zoom × maxFactor`, 최소 1배 | 선형 | `CONTROL_ZOOM_RATIO_RANGE.upper` (API 30+) 또는 `SCALER_AVAILABLE_MAX_DIGITAL_ZOOM` |

**1배 미만(초광각)은 넣지 않았다.** Android는 expo-camera가 `max(1f, ...)`로 잘라서 아예 불가능하고, iOS는 `selectedLens`로 렌즈를 직접 골라야 하는데 이 값이 `localizedName`(로케일에 따라 번역됨)이라 문자열 매칭이 깨지기 쉽다. 초광각이 필요하면 `react-native-vision-camera` 전환과 함께 다루는 편이 낫다.

칩은 10배까지만 연다. 그 위는 디지털 줌이라 화질이 무너지고 매칭이 어려워진다. 더 당기려면 핀치를 쓴다.

## 누끼 파이프라인

```
셔터 → takePictureAsync → 확인 화면 진입
    → CatVision.processCatPhoto(uri)
        ├ 정밀 마스크 성공        → isPreciseCutout = true
        ├ 마스크 실패, 탐지 성공   → 탐지 상자 사각 크롭, isPreciseCutout = false
        └ 둘 다 실패             → hasCat = false, 원본 표시 + 다시 찍기 유도
```

- 처리 전 원본을 긴 변 2048px로 줄인다. 12MP 원본을 그대로 돌리면 느리다.
- 잘라낼 때 경계 상자 바깥으로 18% 여백을 남긴다. 수염과 귀 끝이 잘리지 않게 하기 위함이다.
- 결과 PNG는 캐시 디렉터리에 쓴다. `clearCache()`로 정리한다.
- Android는 누끼 모델을 Play 서비스에서 내려받아야 해서, 촬영 화면 진입 시 `prepare()`로 미리 요청한다. 실패해도 사각 크롭으로 촬영은 이어진다.

## expo-camera의 한계와 후속 결정

아래 두 기능은 `expo-camera`가 API를 제공하지 않아 이번 단계에서 뺐다. 둘 다 카메라 프레임 접근이 필요하다.

1. **실시간 고양이 감지** (프레임 스트림 → 셔터 링 강조). 프레임 프로세서가 필요하다.
2. **탭 투 포커스 / 수동 노출**. 포커스 지점(POI) API가 없다.

두 기능이 필요해지면 `react-native-vision-camera`로 전환하는 결정을 먼저 내려야 한다. 길고양이는 역광·저조도·움직임이 많아 실사용에서 체감 차이가 큰 항목이므로, 실기기 테스트 결과를 보고 판단한다.

## 실기기 확인

- 로컬 빌드: `npm run ios` / `npm run android` (개발 빌드 필요, Expo Go로는 네이티브 모듈이 없어 동작하지 않는다)
- 확인 항목
  - 배율 칩이 기기가 지원하는 값만 뜨는지, 칩 라벨과 실제 화각이 맞는지
  - 핀치 줌이 칩과 같은 배율 축에서 움직이는지
  - 누끼 경계 품질과 처리 시간(`processingMs`)
  - Android 최초 실행 시 누끼 모델 다운로드 후 정상 동작하는지
  - 고양이가 없는 사진에서 안내 문구가 뜨는지
