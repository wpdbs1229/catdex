# 냥도감 알림

피그마 `마이페이지_알림` 시안의 스위치 세 개를 기준으로 알림을 다시 설계한다.
이전 알림 스택(마이그레이션 `000011`·`000019`, `000029`의 기기 등록 RPC)은 분류 체계가
달라 철거하고 새로 만든다.

## 왜 다시 만드나

이전 구조는 설정 토글이 7개(`daily_reminder`, `shared_cat`, `achievement`, `cat_update`,
`social`, `weekly_summary`)였고 이벤트 타입도 7종이었다. 시안은 사용자에게 세 개만 보여준다.
토글과 이벤트 타입을 1:1로 묶어 둔 탓에 분류를 바꾸려면 스키마와 트리거를 모두 손대야 해서,
세부 이벤트가 늘어도 스위치는 세 개로 유지되도록 **분류(category)와 타입(type)을 분리**한다.

## 사용자에게 보이는 분류

| 스위치 | 설명(시안 문구) | category |
|---|---|---|
| 고양이 발견 알림 | 내 주변·관심 지역 새 고양이에 대한 알림 | `discovery` |
| 내 활동 알림 | 내 활동에 새로운 반응이 있으면 알림 | `activity` |
| 이벤트 혜택 알림 | 이벤트, 프로모션, 새로운 소식에 대한 알림 | `marketing` |

### 기본값

`discovery`·`activity`는 기본 켜짐, **`marketing`은 기본 꺼짐**이다.

시안 스크린샷에는 이벤트 혜택이 켜진 상태로 그려져 있지만, 정보통신망법 제50조는 광고성
정보 전송에 사전 수신 동의를 요구한다. 기본값을 켜 두면 동의 없이 보내는 셈이 되므로 기본은
끄고, 사용자가 켠 시각을 `marketing_agreed_at`에 남긴다. 야간(21시~08시) 광고성 발송에는
별도 동의가 필요하므로 `marketing`은 그 시간대에 큐에서 건너뛴다.

## 이벤트 → 분류 매핑

| type | category | 발생 지점 |
|---|---|---|
| `neighborhood_sighting` | discovery | 내 동네에 새 제보(`cat_sightings`)가 올라옴 |
| `neighborhood_new_cat` | discovery | 내 동네에서 처음 기록된 고양이(`cat_encounters` 첫 기록) |
| `cat_rediscovery` | activity | 내가 처음 기록한 고양이를 다른 사람이 다시 만남 |
| `badge_awarded` | activity | 배지 획득(`user_badges`) |
| `post_reaction` | activity | 내 글에 좋아요·댓글(커뮤니티 출시 후) |
| `campaign` | marketing | 관리자가 작성한 `notification_campaigns` 발송 |

## 서버가 내 동네를 알아야 한다

발견 알림의 전제다. 동네는 지금까지 기기(AsyncStorage)에만 있어서 서버가 누구에게 보낼지
알 수 없다. `user_neighborhoods` 테이블에 활성 동네를 올려 두고, 앱이 동네를 감지·변경할 때
같이 갱신한다. 좌표는 저장하지 않고 **행정동/법정동 이름만** 남긴다(기존 구역 정책과 동일).

## 발송 경로

1. 트리거가 `private.enqueue_notification_event()`로 `notification_events`에 행을 넣는다.
   이때 수신자의 설정을 확인해 **꺼져 있으면 애초에 쌓지 않는다.**
2. `pg_cron`이 매분 `private.dispatch_pending_notification_events()`를 돌려
   `notification_devices`의 Expo 토큰으로 밀어 보낸다.
3. 보낼 기기가 없으면 `skipped`로 닫는다.

## 클라이언트

- **알림 설정 화면** — 시안 `마이페이지_알림`. 스위치 3개.
- **알림함** — 시안에 없지만 헤더 벨에 빨간 점이 있어 읽지 않은 알림 개념이 필요하다.
  벨을 누르면 받은 알림 목록으로 가고, 목록 우상단에서 설정으로 넘어간다.
  화면은 `nd` 토큰으로 시안 톤에 맞춰 새로 그린다.
- **권한 요청 시점** — 앱 진입이 아니라 **첫 스위치를 켤 때** 요청한다. 거부당하면 다시 물을
  수 없으므로, 사용자가 알림을 원한다고 밝힌 순간에만 띄운다. 거부 상태면 설정 화면에
  "기기 설정에서 알림 허용" 안내를 띄운다.
- **토큰 등록** — 권한 승인 직후 등록하고, 포그라운드 복귀 때 `last_seen_at`을 갱신한다.

## 단계

| 단계 | 내용 |
|---|---|
| 0 | 이전 알림 스택 철거(크론·트리거·함수·테이블·엣지 함수) |
| 1 | 새 스키마 + 기기 등록 + 설정 화면 |
| 2 | `user_neighborhoods` + 발견 알림 트리거 |
| 3 | 활동 알림(재발견·배지) + 알림함 |
| 4 | 커뮤니티 반응, 이벤트 캠페인 |

## 남은 것

- 커뮤니티 UI가 아직 준비 중이라 `post_reaction`은 스키마만 두고 트리거는 커뮤니티 출시와
  함께 붙인다.
- 이벤트 캠페인 작성 도구는 `docs/admin`의 기존 관리자 화면에 얹는다.
